# Mango Suite Beta9.9.11（以 Beta9.3 为基准）测试版

版本 `1.2.0~beta9.9.11`，安装包 `MangoSuite-1.2.0-Beta9.9.11-RootHide-arm64e.deb`。Beta9.9.11 只修改“倒置时 Dock 避开刘海”（见下两节）；Beta9.9.10 在 Beta9.9.9 基础上新增该开关；Beta9.9.9 在 Beta9.9.1 基础上新增“静止灵动岛黑色光晕”（见文末），其余不变。
适用于已正常运行的 Mango **1.0-Beta9-1 / iOS 16.5 / Dopamine RootHide / arm64e**，沿用现有 iPhone 13 mini 目标。

Beta9.3 专门处理上版启动器仍无法倒置的反馈。日志显示方向2已识别，但窗口旋转后的校验坐标仍为正向，随后修正长期暂停。本版在“启动器重开倒置恢复”开启时改为修正已验证 Mango 启动器的内容根视图，使用子层坐标校验，并为其保存独立所有权；停用或返回正向时恢复自身变换。

## Beta9.9.11：按 Beta9.9.10 真机日志修正刘海处上划，并补 Dock 诊断

Beta9.9.10 的日志里刘海正中起手的第一个触点在离边约 38 点处，而系统底边识别区只有 33.8 点；只在起手那一次调用里临时放宽没有效果，说明系统在那之前就已按原识别区判定。结果是这次触摸不被当成边缘手势，刘海下方 App 的按钮/交互直接收到了上划。本版改为：倒置且开关开启时，主屏手势的底边识别区**持续**保持至少 50 点（13 mini 刘海一侧的安全区高度），正向、横屏或关闭开关时还原为系统原值。识别区够了，系统会先挂起 App 的这次触摸，上划被识别后取消它，App 的按钮不再被误触；点按仍照常传给 App。刘海两侧的识别区也随之变为 50 点。

同一份日志里没有任何 `DOCKLIFT`，而安装时的结果在开始记录之前，无法区分“没挂上”“没被调用”“调用了但没判定为倒置”。本版新增只读的 `DOCK status` 行（记录期间约每 2 秒检查、变化时写入）：挂钩结果、调用次数、最后一次进度与抬升量、是否判定倒置，以及设备上浮动 Dock 窗口、Dock 视图的真实类名和根控制器里与布局/进度相关的方法名。Dock 抬升逻辑本身未改，下一版据此对准 16.5 上真实的方法。

## Beta9.9.10 相对 Beta9.9.9 的唯一改动：倒置时 iPad 样式 Dock 避开刘海

用 Lynx 2 的“浮动 Dock”打开 iPad 样式 Dock 后，倒置时 Dock 底部被刘海挡住一部分，刘海那一段也无法从“底边”上划回主屏或唤出 Dock。Lynx 只是打开系统自带的浮动 Dock（`SBFloatingDock*`），所以修在系统 Dock 上，放在“倒置方向与小芒”模块里，由新开关 **屏幕倒置 → 倒置时 Dock 避开刘海**（`DockNotchEnabled`，默认开启）控制，约 0.5 秒内生效。

- **抬多高**：13 mini 屏幕 375×812 点、476 ppi、原生缩放 2.88，1 点 ≈ 0.1537 mm；刘海（传感器外壳）约 26 mm 宽、5.35 mm 高（网上泄露/实测数据，无官方点数），即约 169×35 点。状态栏 50 点 ≈ 7.69 mm 与 iPhone 13 的 47 点 ≈ 7.79 mm 物理高度一致，数据自洽。倒置时 Dock 完全抬起的位置再抬 **35 点**，Dock 离刘海下沿的距离等于正向时离屏幕底边的距离。
- **手指行程不变**：系统按展开进度（0 收起、1 完全抬起）摆放 Dock 后，再按 `35 × 进度` 额外上移；系统把手指位移换算成进度的部分没动，所以同样的划动距离 Dock 抬得更高。只在 Dock 的底边真的朝向刘海时才抬，正向、横屏、关闭开关都是 0，且自动还原、不叠加。
- **刘海处上划**：刘海没有触摸层，手指从刘海上滑进来时第一次被识别的位置离边约 35 点，超出系统底边识别区。倒置时，只要起手点在刘海水平范围内（中心 ±95 点），就把主屏手势这一次起手的底边识别区临时加宽 35 点，处理完立即还原；刘海两侧和其它触摸不变。
- **依据与边界**：类名方法名来自 iOS 14.5 头文件转储，16.5 上未核实；签名不符时记录 `NO DOCK LIFT` / `NO HOME EDGE FIX` 并完全不安装。主屏倒置时抬高后的 Dock 可能压到最下一行图标或页码点（主屏布局未改）。开启调试记录后，World 日志有 `DOCKLIFT progress=… lift=…` 与 `HOMEEDGE notch-touch …`。未连接手机，没有真机验证。

## Beta9.9.1 相对 Beta9.3 的唯一改动：倒置时通知上下滑方向

Beta9.3 的通知条（`MangoPillElement`）手势修复只在“调整大小”手势入口匹配后才会安装，入口缺失或被包装时通知条没有任何修复。本版改为独立安装，并且不再靠全局挂钩 UIPanGestureRecognizer 去改位移：手势结束时，若方向为1/2、手势在已拥有的灵动岛窗口内且视图到屏幕固定坐标系为半圈倒置，就把传给原函数的手势换成转发代理，代理的 `translationInView:` 只把纵向位移取反，其余消息转发，识别器本身不改。判定条件与 Beta9.3 对“调整大小”手势使用的一致，仍由“通知上下滑动方向修复”开关控制。

Beta9.9.1 依据 Beta9.9 的设备日志修正判定：日志显示倒置时（方向2）灵动岛窗口已被翻转，但通知手势走的是 `_handleResizePan:`，其视图所在窗口不是灵动岛窗口、到屏幕固定坐标系为恒等映射（`apertureTarget=0`、`actualViewInverted=0`），旧判定要求“属于灵动岛窗口且被翻转”，因此从未生效，没有任何位移被修正。现在改为：方向2且手势视图到固定坐标系为未翻转的正向映射时，翻转手势结束时的纵向位移与速度；视图本身已翻转时不再翻转。通知条入口同样使用该判定。日志仍记录每个判定条件。

其余代码（倒置、常态显示、玻璃、分屏、小芒、设置页）与 Beta9.3 相同。未连接手机，没有真机验证；开启调试记录后每次结束手势会在 World 记录写一行 `PAN ended … localY= handlerY=`。更改后需要重新启动用户空间。

## 安装和使用

覆盖安装完整 MangoSuite 包，然后在多巴胺中重新启动用户空间。
进入 **设置 → Mango 整合**，设置页按“总开关 / 灵动岛·静止态 / 灵动岛·玻璃与边缘 / 背景颜色自适应 / 屏幕倒置 / 调试 / 使用”分组，每组有一行说明（哪些开关需要重启用户空间）。已有开关和原生倒置偏好保留；不会重写 Mango 原版模块。
七项新开关分别保存，默认开启六项修复；边缘采色默认关闭。新开关和采色参数在模块加载后约0.5秒内刷新。
总开关、原来的四个模块开关仍需要重启用户空间；原生倒置仍按原来的保存及 Respring 流程应用。
“启动器重开恢复”依赖分屏模块，“调整大小保持倒置”和“通知上下滑方向”依赖倒置方向模块。关闭对应旧模块后，这些新修复不会单独加载它。

| 独立开关 | 本版实现 |
|---|---|
| 椭圆轮廓与四角修复 | 统一投影后的圆角轮廓，限制退化半径；用一个轮廓绘制边缘，关闭对应原生 specular，避免两侧重复描边 |
| 启动器重开倒置恢复 | 通过启动器内容根视图和子层坐标修正，避免窗口坐标未响应导致长期暂停；处理 Dock／资源库重开后的变换重置与原生场景映射变化 |
| 液态玻璃过渡动画修复 | 读取当前 presentation 几何，连续更新同一轮廓；保留 Mango 玻璃内容，避免分别缩放左右端帽 |
| 调整位置大小保持倒置 | 根视图／内容布局时保持已确认的倒置坐标空间；新的有效几何可恢复先前被暂停的修正 |
| 短通知黑色光晕修复 | 针对 Mango 通知提供视图，建立显式阴影路径和最低模糊半径，在父层绘制，避免内容高度和自身裁剪影响 |
| 灵动岛边缘实时采色 | 四方向环外采样，按颜色面积和饱和度选择色调；平滑更新光学渐变，不保存截图 |
| 倒置时 Dock 避开刘海 | 倒置时完全抬起的 iPad 样式 Dock 按展开进度多抬 35 点露出刘海，手指行程不变；刘海水平范围内起手的底边上划临时加宽识别区 35 点 |
| 通知上下滑动方向修复 | 在已验证且确实倒置的灵动岛通知坐标内，对通知结束手势的纵向位移和速度查询补偿，覆盖 Aperture 和 MangoPill 两个入口 |

粗细可调 **0.5～4点**，动态程度 **0～1**。动态程度影响颜色响应、采样频率、亮度及细微高光游动。采样通常为每秒4～8次；捕获单次超过20毫秒时降到每秒2次。静止且未开启采色时暂停逐帧刷新，过渡几何最多30帧／秒；分屏揭示恢复最多60帧／秒、持续1.2秒。
采色优先使用运行时存在的系统屏幕图像接口；不能使用时尝试 SpringBoard 背景窗口，日志区分 `display-pixels` 和 `springboard-window-pixels`。后者不能保证包含前台 App 的全部画面。采集失败时移除采色效果或使用已启用的普通白色边缘，不用虚构颜色代替。需要真机确认该设备支持哪条采色路径。

## 一键日志

进入 **设置 → Mango 整合 → 调试日志与一键提取**：

1. 点击 **开始／重新开始记录**。
2. 复现异常；每个记录会话持续20分钟，每模块最多256KB。
3. 回到页面，点击提取全部日志，或按玻璃／光晕／采色、分屏启动器、倒置与手势分别提取。
4. 在系统分享页面保存或发送生成的 `.txt` 文件。

默认不记录。记录只包含时间、会话、尺寸、方向、动画几何、采色可用状态和修复开关，不保存通知文字、封面或截图。重启／重新记录后请以日志里的会话号区分。旧的 shell 提取工具仍包含在包中。

一键提取只保留当前记录会话。启动器日志新增 `correctionTarget=launcher-content-root`、`rootModel`、`rootBasis`、`rootEligible`。请安装后重新点击“开始／重新开始记录”，再复现并提取启动器与分屏日志。

## 静止灵动岛黑色光晕（待真机验收）

设置 → Mango 整合 → 灵动岛外观 → “静止灵动岛黑色光晕（上黑下透）”，默认开启，下方是三个控制：**黑色浓度**（0–100%，默认 100%）和 **渐隐位置**（黑色在胶囊高度的多少处完全消失，30%–100%，默认 55%，越小黑色越靠上）和独立开关 **下沿提亮**（下边缘的柔光和一圈下沿更亮的细玻璃边，默认开启，关掉后只剩上黑下透）。灵动岛形状不变。

效果：在静止胶囊上叠一层从顶部纯黑向下直线渐隐的黑色；同时把玻璃底也按同方向渐隐，下半真正透出壁纸；再加一圈下沿提亮和一条下沿更亮的细玻璃边（液态玻璃感）。这是对 Beta9.9.5 的修改：真机照片显示圆形光晕在小胶囊上是弧形“碗”边、下半发灰像个洞，所以改成直线渐变。渐变是自己画的，不是 Mango 的绘制代码；滑杆是本套件自己的，与 Mango 的“黑色光晕透明度/范围”无关。

玻璃底的渐隐是给玻璃底视图加一个渐变蒙版（只加/只改自己的蒙版，别人的蒙版不动；关闭开关即移除）。若发现玻璃折射在加了蒙版后消失或闪烁，请关闭这个开关并发日志——Mango 的实时玻璃视图带蒙版是否正常渲染只能真机确认。

来通知、放音乐、展开等活动态仍由 Mango 原生接管，这一层随活动透明度反向淡出（与玻璃底同一交接）。日志里的 `[GLOW] created ... glass=` 说明底下是 Mango 玻璃（1）还是 UIKit 回退（0）。

### Beta9.9.8：随背景明暗自动切换（开关“随背景明暗自动切换”，默认开启）

真机白底照片显示：黑色渐隐要经过一大段灰色，像脏灰；下半透明、下沿的白色提亮在白底上看不见，胶囊没有下边缘，像被切开。所以按背景明暗在两种“收尾”之间自动切换：

- **清透（深色或有颜色的背景）**：与之前相同——下沿柔光（受“下沿提亮”开关控制）和下沿更亮的细玻璃边。
- **磨砂（偏亮的背景，如白色页面）**：下半加一层淡灰磨砂 + 一圈全周细轮廓线，始终是一颗完整的胶囊；此时下沿提亮不显示（白底上看不见）。

背景亮度取自岛周围的一圈像素（复用边缘采色的取样代码，从不取岛自己的像素），约每秒一次；单次取样超过 20ms 时降到每 3 秒一次。亮度大于 0.66 切到磨砂，小于 0.55 切回清透，中间保持原样（防抖）；取样失败时保持当前样式。切换有 0.4 秒过渡。关闭开关则始终用清透样式。日志里 `[GLOW] finish=… luminance=…` 记录每次切换，`background-luminance=… capture=…`（调试记录开启时）记录取样结果，用来校准阈值。

### Beta9.9.9：手动“始终使用磨砂样式”

Beta9.9.8 真机反馈“自动切换似乎没起作用”。最可能的原因是自动切换依赖的截屏取样没有拿到前台 App 的画面（只取到 SpringBoard 自己的窗口时，白色 App 页面会被判成深色），但电脑上无法验证。新增开关 **始终使用磨砂样式（不随背景变化）**，默认关闭：打开后不取样，直接固定为磨砂样式，同时用来区分“取样没生效”和“磨砂这层没画出来”。开调试记录后，`[GLOW] finish=… luminance=… adaptive=… forced=…` 记录每次样式切换（luminance=-1 表示取样不可用），`background-luminance=… capture=display-pixels|springboard-window-pixels|…` 记录取样路径。
