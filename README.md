# Mango Suite Beta9.6 崩溃隔离诊断版

Suite `1.2.0~beta9.6`，用于 Mango **1.0-Beta9-1 / iOS 16.5 / Dopamine RootHide / arm64e**。

用户确认 Beta9.5 仍未修复，上滑通知仍进入安全模式。当前没有已证实的崩溃原因，也没有已通过真机的修复。本版提供完整隔离和直接提取崩溃报告的工具，原来的七项问题仍未解决。

## 安装与隔离

覆盖安装完整 `MangoSuite-1.2.0-Beta9.6-RootHide-arm64e.deb`，在多巴胺中重新启动用户空间，然后重新打开设置 App。

**设置 → Mango 整合 → 通知崩溃隔离** 默认开启。新的进程启动时，整合包的静止玻璃／轮廓／光晕／采色、World／小芒、分屏和 backboardd 自适应模块全部停止加载。整合加载器只保留 Foundation 启动观察器和设置页，Mango 原版继续自行加载。

原有选择与 Mango 原生倒置偏好保留，不改原始二进制和授权。隔离下，整合补丁的外观和倒置补偿不会生效，原有位置、绘制和最终动作问题可能继续存在。不能把这种状态称为修复。

更改隔离开关后必须重新启动用户空间。只覆盖安装或更改开关不能移除旧进程里已经加载的处理。关闭隔离会恢复此前补丁路径，上滑崩溃仍未定位，因此关闭隔离不是已验证的解决办法。

## 先取已有崩溃报告

进入 **调试日志与一键提取 → 提取最近 SpringBoard 崩溃报告与日志**。无需为了提取报告再反复触发通知上滑，也不必先开始新的记录会话。

按钮会分享当前会话日志，以及可访问候选目录中最近最多3份合格的 SpringBoard `.ips`／`.crash` 原文报告。文件必须属于当前用户、是完整普通文件、进程标识确为 SpringBoard，每份不超过2MB；拒绝符号链接、硬链接、超限及其他进程报告，原文件不改动。扫描有数量和读取上限；位置不同、权限受限或报告过大时可能无法取得，界面会说明。未取得报告不表示没有崩溃。系统报告含原始系统信息，分享前可查看。

请提供与通知上滑时间对应的报告和具体时刻。报告按文件时间排序不代表自动对应到这次动作。

## 核对实际加载状态

开始／重新开始记录后约两秒，Startup 日志记录：

- `compiled-loader=1.2.0~beta9.6`：当前观察器的实际编译版本。
- `plannedMask=0 isolationAtStartup=1`：本进程启动时没有计划加载整合修复模块。
- `suiteImagesCurrently=0`：当时 SpringBoard 的 dyld 列表没有整合目录的模块镜像；若非0，不能视为完成隔离。
- `repairImagesAnyPath=0 legacyOrientationImage=0`：同时核对整合目录之外的同名修复模块和旧方向模块；目录内为0并不排除外部副本。
- 已加载 Mango／注入镜像的文件名与内存 UUID，用于比较旧代码及其它注入。最多记录64个相关镜像，标明是否截断。

这里记录的是镜像存在和启动决策，不判断每个挂钩是否安装，也不能单独排除 Mango 原版、其它插件或 backboardd 旧进程的影响。隔离和总开关关闭时仍可启用 Startup 记录。其余模块不加载时没有相应的新日志是预期。

新记录会话会过滤旧会话，因此先导出已有记录，再开始新会话。每会话20分钟，每模块256KB；整合日志不保存通知文字或截图，系统崩溃报告另行复制原文。

## 验证与后续

本版执行实际生产隔离策略、设置保留、崩溃报告筛选与完整复制、关闭总开关仍能记录、内存 UUID 边界和检测已加载镜像的宿主测试，并重新编译 iOS 16.5 arm64e 代码。证据见交付目录的 build-validation.json 与 package-verification.json。没有连接手机，不能宣称上滑安全模式已消失。

需要真实崩溃报告与隔离后的启动记录才能继续缩小范围：隔离后若仍崩溃，先核对旧模块、其它注入和报告线程；若未再出现，也仅是排查线索，不能直接断言哪个处理是原因。最终修复仍需调用栈与真机验证。
