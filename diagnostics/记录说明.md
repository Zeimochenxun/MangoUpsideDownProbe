# MangoSuite Beta8.2 异常记录

适用设备：iPhone 13 mini、iOS 16.5、多巴胺 RootHide，Mango 已正常授权。

已确认的现象：所有播放器都没有灵动岛媒体内容或指示；分屏启动器偶尔回正，随后灵动岛上下划行为改变，而桌面、锁屏仍倒置。这说明要重点检查局部窗口与 Mango 的方向处理。是否是方向读数变化、窗口变换被覆盖，仍需运行记录区分。

脚本只记录指定类的调用、复制现有日志，不修改设置、二进制或授权，也不会自动重启 SpringBoard。目前没有连接你的手机；以下命令需要你在手机上执行。已有手机记录在创建 SpringBoard 远程线程时失败，尚未成功附加。

**当前先保留并发送已有压缩包，不要反复重试附加。** `objsee.log` 是失败日志；同目录的 `metadata.txt` 是版本、安装路径和日志来源信息，两者用途不同，自动生成的 `.tar.gz` 已包含它们。过滤器修正不会自行解决线程创建失败。

## 在手机执行

把 `capture-objsee.sh` 放到手机 `/var/mobile/Documents/`，在 NewTerm 或已经登录手机的交互式 SSH 终端执行。不要在 Windows PowerShell 里直接运行这些 `sh` 命令。需要 sudo 时输入手机的 mobile 密码，密码不用发给我。

### 1. 媒体缺失：约 30 秒

```sh
sh /var/mobile/Documents/capture-objsee.sh media
```

保持倒置，先停在桌面约 3 秒，打开一个能稳定复现的播放器播放，再返回桌面约 10 秒；从控制中心暂停、继续播放，再回到桌面。只需要测一个播放器。随后按 Ctrl-C，等待终端显示 `Saved` 和 `Archive`。

脚本会保存显示链的 objsee 调用及 Idle、World 日志。Idle 的状态日志只在状态变化时输出；没有新行不能直接证明没有媒体事件。它显示 `activity=0` 也只能证明该 host 当时没有可见活动，不能单凭这一项判定是谁阻止了媒体创建。

保存文件后，用你平时的方法 respring，再进行下一次 objsee 记录。

### 2. 启动器回正与手势改变：同一次记录

```sh
sh /var/mobile/Documents/capture-objsee.sh orientation
```

开始时让桌面、启动器处于倒置。按平时方式使用启动器。若它回正，不切换倒置开关、不立即 respring；接着各做一次灵动岛上划、下划，观察结果，并确认桌面仍倒置。然后按 Ctrl-C 保存。

尽量同时录屏，或记下回正发生在记录开始后的大约第几秒。默认 objsee 调用行没有逐事件时间戳，因此“回正 → 上划 → 下划 → 停止”的顺序尤其重要。没有固定触发规律时，每次记录最多约 60 秒；没有复现也停止，不必一直追踪 SpringBoard。objsee 本身可能影响时序，记录中未复现不等于问题已经修复。

### 3. 偶发问题已经出现：先取现有日志

如果没有开 objsee 时启动器已经回正，保持当时状态，先执行：

```sh
sh /var/mobile/Documents/capture-objsee.sh logs
```

这一模式不需要 objsee，只复制现有日志。先保存，再考虑切换倒置开关或 respring，以免丢失现场线索。

## 发回哪些文件

输出在手机 `/var/mobile/Documents/MangoSuiteDiagnostics/`。把终端显示的对应 `.tar.gz` 文件发回来；如果没有成功打包，发送对应目录即可。RootHide 下以执行脚本的终端看到的路径为准，可用 Filza 或同一 SSH 连接取回。

同时说明实际播放器、是否在记录期间复现、回正前最后一个操作、回正后上划和下划分别做了什么。若有录屏，一并发送。也可以填写目录里的 `notes.txt`；编辑后要重新压缩目录，自动生成的压缩包不会随之更新。

脚本分别保留 RootHide shell 与 `/rootfs` 两个候选位置的日志，`metadata.txt` 记录各文件来源。它们缺失会明确标注，不需要自己猜路径或清空原始日志。

## 这轮记录的边界

采用 `-A0`，只限定已确认的类或类家族，再从记录中筛选相关 selector。方向记录覆盖 Beta8 原有启动器、Mango 方向处理与灵动岛窗口/控制器；媒体记录覆盖原生容器、`SAUI*` 元素与玻璃视图。每轮仍只记录约 30–60 秒。

手机输出的配置证明所装 CLI 将每个 `-c`、`-m`、`-i` 参数拆为独立条件，与之前核对的上游合并版本不同。独立 include 条件之间是 OR，旧脚本的 method 条件可能匹配 SpringBoard 中其它类的同名方法。此修订只用 `-c`，使新旧解析方式都保持限定的类范围；已有尝试未成功注入，不能当作有效追踪。

**普通 objsee 不输出方法返回值。** 本方案不会把 `mango_currentInterfaceOrientation` 的调用误当成读到了方向数值，也不会把 `setTransform:` 的出现误当成已知道变换矩阵。现有 World 日志中的 `WORLD`、`SKIP`、`SUSPEND` 和 Idle 状态才提供部分实际值；若仍无法区分两个方向故障候选，再针对缺失值补一次窄范围诊断。

**Ctrl-C 停止的是日志接收端。** 注入的 tracer 不会立即卸载；目标进程后续发送失败才会触发清理。因此先等脚本复制、保存完成，再用平时的方法 respring，之后再开始另一轮记录。

脚本已在本机验证 shell 语法、正常结束、模拟附加失败、模拟 Ctrl-C 后的日志保留与打包，以及仅取现有日志模式。这些检查使用本地替身，不代表已在手机成功附加。

参数和过滤规则核对自 [过滤器合并修复](https://github.com/EthanArbuckle/objsee-ios/commit/8092d31ee437769ce798361cbf1dad6dbd5fe6ee)及其前后版本；事件字段见 [objsee 官方说明](https://github.com/EthanArbuckle/objsee-ios/tree/894d283d70c9e40896911290db084d036c135cf1)。停止行为依据 [transport 实现](https://github.com/EthanArbuckle/objsee-ios/blob/894d283d70c9e40896911290db084d036c135cf1/src/libobjsee/transport/transport.c)。尚未据此修改生产包。
