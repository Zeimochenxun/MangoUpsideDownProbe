# Beta8.4.1 运行时诊断

完整包：`MangoSuite-1.1.0-Beta8.4.1-Diagnostics-RootHide-arm64e.deb`，版本 `1.1.0~beta8.4.1`。

此包沿用 Beta8.4 的修复行为，仅增加只读诊断和采集脚本。它不是新的修复承诺；Beta8.4 用户实测中媒体内容缺失仍存在，另有分屏启动器偶发回正、随后灵动岛上下滑语义改变，而桌面／锁屏仍倒置的现象，尚未找到固定触发步骤。已有日志尚缺完整几何和分屏退出记录。此诊断包及采集脚本尚未在手机上验证。

诊断从每个编译单元首次使用记录器起分别计时 **1200 秒**（约加载后 **20 分钟**），每个新日志严格限制在 **256 KiB** 内。采集脚本不会开启注入、修改偏好或开关、改变方向、控制进程或执行重启，也不会读取全部 Mango 偏好、授权数据或媒体标题。它立即复制限定日志的末尾，每个候选文件最多 **1 MiB**，随后打包退出；不会延长模块记录时限。

按顺序操作，每次只做一步：

1. 安装上述完整诊断包，保留 Mango 主插件。
2. 在多巴胺中执行一次完整的“重新启动用户空间”。
3. 重启完成后，在 20 分钟内播放音乐，复现媒体内容缺失。
4. 打开 Mango 分屏启动器。
5. 正常使用分屏启动器，观察是否偶发回正。
6. 对灵动岛上划一次，观察结果。
7. 对灵动岛下划一次，观察结果。
8. 无论症状是否触发，都在 20 分钟窗口内，在终端以通常的 mobile 用户运行下面这一个命令。

```sh
sh /Library/MangoSuite/Diagnostics/capture-runtime.sh
```

命令立即打印绝对输出路径，形如：

```text
/var/mobile/Documents/MangoSuiteDiagnostics/runtime-20261003-120000-AbCdEf.tar.gz
```

用同一终端看到的路径或 Filza 取回这个 `.tar.gz` 文件。若打包失败，终端会打印保留的快照目录；取回该目录即可。日志不存在、无权限、非普通文件或读取失败都会写入 `metadata.txt`，脚本不会要求 sudo。发送这次输出及简短操作顺序，同时记录分屏启动器是否回正、桌面／锁屏的方向及灵动岛上下滑的实际结果；没有出现症状则写“未触发”。不必反复执行重启或更改开关。

快照中的 `diagnostic-idle-*`、`diagnostic-world-*`、`diagnostic-split-*` 分别来自 `MangoSuiteDiagnostics/Idle.log`、`World.log`、`Split.log`。`shell` 和 `rootfs` 是两个独立候选，分别保留来源路径、时间和文件状态；仅凭文件存在不能认定它由本次进程产生。

`legacy-idle-*` 与 `legacy-world-*` 是旧路径的补充历史，名称单独区分。尤其 `/rootfs` 中的旧日志不能当作本次诊断包的实时证据。`metadata.txt` 另记录采集时间、系统版本和已安装的 Mango／MangoSuite 包版本；没有日志的空快照也能帮助定位路径或权限问题。
